## Chapter 4: Advanced cuDF: Strings, Datetimes, Nulls, and Categoricals — Flashcards

| # | Front (Question) | Back (Answer) |
|---|-----------------|---------------|
| 1 | cuDF Series constructor: what does nan_as_null default to, and what does it do? | Defaults to True. Any np.nan encountered when building a Series/DataFrame from data is converted into an actual null entry in the validity bitmask, not kept as a distinct float value. Exam tip: this differs from pandas, where NaN remains a real float that isna() also flags as missing. |
| 2 | Which cuDF string method extracts regex capture groups into separate columns? | Series.str.extract(pattern). Returns a DataFrame with one column per capture group. .str.findall() returns matches as lists instead; .str.match() only tests start-of-string matching. |
| 3 | cuDF categorical codes: what integer type is used for 300 unique categories? | int16. Rule: int8 up to 127 categories, int16 up to 32767, int32 beyond that. Exam tip: cuDF/Arrow always picks the smallest sufficient signed integer type for codes. |
| 4 | How does cuDF represent missing values in a string column? | Via a native Arrow-style validity bitmask, same mechanism used for all cuDF column types — no sentinel empty string or float NaN needed. Exam tip: this is a true 'null', distinguishable from an actual empty string ''. |
| 5 | cuDF regex support: what major feature is NOT supported? | Variable-length lookbehind assertions (and some other advanced PCRE features) are unsupported. Exam tip: for these patterns, fall back to .to_pandas() + Python re, then cudf.from_pandas() to bring results back to GPU. |
| 6 | How do you convert a numeric-looking cuDF string column to numeric, coercing bad values to null? | cudf.to_numeric(series, errors='coerce'). astype() has no errors='coerce'/'ignore' option and will fail on unparseable strings. |
| 7 | Command to compute daily mean of a numeric column with a datetime64 index in cuDF? | df.resample('D').mean() — supports standard pandas offset aliases and runs the aggregation on GPU. Avoid rolling('D'), which computes a moving window, not fixed daily buckets. |
| 8 | When should a string-heavy workload stay on CPU (pandas) instead of cuDF? | When it needs regex features cuDF's engine doesn't support (e.g., variable-length lookbehind, some backreferences), or heavy NLP-style processing where per-row Python UDF overhead and unsupported ops dominate any GPU speedup. |
| 9 | Why does converting a low-cardinality string column to categorical dtype save GPU memory? | The unique values are stored once in a small dictionary; the column itself becomes an array of small integer codes (int8/int16/int32) referencing that dictionary, drastically shrinking the buffer versus repeating full strings per row. |
| 10 | cuDF isnull() vs pandas isna() on a float column with real NaN — key exam gotcha? | Because cuDF's constructor default (nan_as_null=True) turns NaN into null on ingestion, isnull() reports it as missing the same way pandas isna() would — but the underlying representation differs: cuDF stores it as a true null in the bitmask, not as a retained float NaN value. |
| 11 | Which cuDF string method tests whether a pattern exists anywhere in each string (boolean result)? | Series.str.contains(pattern, regex=True). Set regex=False for a literal substring search, which is faster since it skips the regex engine. |
| 12 | How to drop rows with any null values in a cuDF DataFrame? | df.dropna(). Row-wise (axis=0) dropping is the well-supported, heavily-tested path; be cautious with column-wise (axis=1) dropna, which has historically had more limited support than in pandas. |
