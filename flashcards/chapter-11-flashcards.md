## Chapter 11: Profiling and Optimization: DLProf, Nsight, and Memory Efficiency — Flashcards

| # | Front (Question) | Back (Answer) |
|---|-----------------|---------------|
| 1 | DLProf vs Nsight Systems — primary distinction? | DLProf gives DL-specific aggregated training metrics (GPU util %, Tensor Core %, iteration time) and can export a timeline viewable in Nsight Systems. Nsight Systems independently shows the full system-wide timeline (CPU, GPU, memcpy). Exam tip: choose DLProf for aggregated DL run metrics, Nsight Systems for pipeline timeline stalls. |
| 2 | Nsight Systems vs Nsight Compute — granularity? | Nsight Systems = system-wide timeline (CPU/GPU sync, memcpy, NVTX ranges). Nsight Compute = single-kernel deep dive (occupancy, registers, memory throughput). Exam tip: pipeline-spanning bottleneck → Nsight Systems; single-kernel bottleneck → Nsight Compute. |
| 3 | Command to launch a Nsight Systems timeline profile? | `nsys profile -o report python train.py`. Exam tip: produces a .nsys-rep (or legacy .qdrep) viewed in the Nsight Systems GUI. |
| 4 | Command to profile a kernel with Nsight Compute? | `ncu --set full -o kreport ./app`. Exam tip: Nsight Compute has much higher per-launch overhead than Nsight Systems — use it only on already-identified suspect kernels. |
| 5 | DLProf CLI basic usage? | `dlprof --mode=pytorch python train.py` (or `--mode=tensorflow`). Produces a Nsight Systems-viewable report plus a CSV/JSON metrics summary. Exam tip: DLProf wraps a training script, not a general-purpose app. |
| 6 | Why use RMM pool allocation? | RMM's pool allocator pre-allocates a large device memory block and sub-allocates from it, avoiding repeated cudaMalloc/cudaFree driver calls. Exam tip: use it when a workload (e.g., cuDF ETL) does many small/frequent allocations. |
| 7 | FP16 mixed precision memory savings vs FP32? | ~50% memory reduction (2 bytes vs 4 bytes per value). Exam tip: also enables higher Tensor Core throughput, but risks gradient underflow — requires loss scaling. |
| 8 | What fixes gradient underflow in FP16 training? | Loss scaling — scale the loss up before backward pass, unscale gradients before the optimizer step. Exam tip: Automatic Mixed Precision (AMP) handles this automatically. |
| 9 | TF32 vs FP16 — key exam distinction? | TF32 (Ampere+) keeps FP32's 8-bit exponent (same dynamic range) but reduces mantissa to 10 bits, requiring no code changes and no loss scaling. FP16 has a smaller 5-bit exponent range and needs loss scaling. Exam tip: TF32 is the safer numerical default. |
| 10 | Nsight Systems timeline shows low GPU utilization with many small gaps between kernel launches — likely fix? | Increase batch size to amortize kernel-launch overhead across more computation, raising GPU/Tensor Core utilization. Exam tip: this is a batching fix, not a profiling-tool-switch fix. |
| 11 | How to reduce host-to-device transfer frequency? | Batch transfers into larger, less-frequent copies; use pinned (page-locked) host memory; overlap transfer with compute using CUDA streams/prefetch. Exam tip: excessive small HtoD memcpy blocks are visible on the Nsight Systems timeline. |
| 12 | Reproducibility practice for production ADS pipelines? | Pin container image tags (specific NGC release, not 'latest') and pin library versions (RAPIDS, cuDF, PyTorch); fix random seeds; set deterministic algorithm flags. Exam tip: 'latest' tags are a commonly flagged production anti-pattern. |
